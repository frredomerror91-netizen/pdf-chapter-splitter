# v1.5.0：自适应 OCR 并发与准备提速

大型扫描版资料可以按分块数量和电脑资源自动增加独立 OCR 实例，准备好首块就开始识别。进度区显示输入准备、OCR 页数、已完成分块和运行实例，等待阶段更容易判断。

## 新增与改进

- 100 页及以上均匀分块，每块最多 50 页；默认最多 4 个实例；主动选择自动模式时最多 12 个，资源足够时每块一个实例。
- OCR 设置新增并发上限，默认 4，0 为主动选择自动模式，1–12 为手动上限。实例数量同时受 CPU 与可用内存预算约束。
- 分块准备与独立 OCR 实例同时工作，逐页更新准备进度并检查取消。
- 失败或取消后可复用已验证的输入分块和已完成 OCR 结果，损坏缓存会重新处理。
- PDF 缺失对象采用一次扫描的恢复索引，减少重复读取整份资料。
- 独立实例直接启动并按所属路径回收，保留常规 OCR 服务。

## 使用与升级

1. 关闭旧版窗口，完整解压本地源码包，使用新版目录中的启动入口。
2. 安装运行依赖后，在“OCR 设置”选择完整的 Umi-OCR 便携版主程序。
3. 默认并发上限为 4，每实例最多 2 个计算线程。希望进一步控制资源占用时，可设为 2 或 3；主动设为 0 时使用自动模式。
4. 选择 PDF，分析或一键 OCR，识别后校对章节再导出。

源码包需要 Windows、Python 3.10+ 和 Tkinter；Umi-OCR、模型、教材、个人设置与处理结果单独保留。保留原目录内的个人配置和分块检查点，可继续未完成任务。

## 本轮验证

- Windows 上 104 项回归测试和全部应用模块编译检查通过，覆盖自动并发、资源限制、设置保存、准备取消、流水线、断点恢复与章节导出。
- 使用真实 Umi-OCR Rapid v2.1.5 启动 7 个独立端口，对 7 个扫描分块同时 OCR；活动实例峰值为 7，合并页序与文字正确，原文件哈希保持不变，私有实例全部退出。一次启动失败由有限重试恢复。
- 对截图中的 306 页教材做只读准备对比：旧流程复制首个页面约 1.9 秒，新流程生成前 44 页输入约 2 秒，页数与原文件哈希校验通过。这是分块准备耗时，不代表整本 OCR 总耗时。

原始 PDF 保持不变；对象结构损坏不能恢复其原本不存在的内容。
