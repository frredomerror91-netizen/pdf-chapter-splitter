# v1.6.0 使用说明

适用于本地 v1.6.0 源码版。基本流程是：添加 PDF → 选择排队或并行 → 分析 → 分文件校对 → 导出。更新功能在软件内完成检测、下载和校验，不会自动安装。

## 首次安装

需要 Windows、Python 3.10 或更高版本及 Tkinter。完整解压源码包，在软件文件夹打开 PowerShell：

~~~powershell
python -m pip install -r requirements.txt
python .\split_pdf_by_chapter.py
~~~

也可双击 `启动章节拆分工具.cmd`。安装依赖与启动须使用同一 Python 环境。

## 添加和调度多份 PDF

1. 点击文件任务栏“＋ 添加”，或当前文件设置中的“添加 PDF”，可一次多选，也可继续追加。
2. 相同规范路径会去重；名称相同但位于不同目录的文件会分别加入。
3. 在任务栏选择“排队处理”或“并行处理”。默认排队，逐份完成分析；并行模式默认两份，可设置 1～4 份。
4. “处理全部”启动列表中的文件；“处理选中”仅处理选中项。空选不会自动处理全部。
5. 点击条目切换当前文件。按 Ctrl 点击可选择多份任务用于批量导出或移除。右侧显示当前文件的章节，不把多份文件的章节混成一张表。

运行中改变调度模式和文件数上限，只影响后续派发，不强杀在途任务。更改性能档位在本轮任务结束后的下一轮应用；资源摘要显示实际使用档位。

单份失败后，其余任务继续。选择失败项点击“处理选中”可重试；当前项可用底部取消按钮停止，也可以“取消全部”。移除正在运行的文件会先取消，释放资源后再移除。

任务列表只在本次会话中保留，关闭重启后需要重新添加。不要把这一点与 OCR 的磁盘检查点恢复混淆。

## 配置扫描版 OCR

有文字或可靠章节书签的 PDF 可直接分析。扫描版需完整 Umi-OCR 便携版：

1. 保留 `Umi-OCR.exe` 及旁边的 `UmiOCR-data` 文件夹。
2. 点击“识别章节 → 设置”，选择主程序并保存。
3. 选择扫描 PDF，点击“扫描版：OCR 并分析”，强制重新识别；普通“分析章节”在启用自动 OCR 且缺少文字层和可用章节书签时进入 OCR。

配置完整本地引擎后，工具会建立由自己管理的私有实例。仅配置现有 HTTP 服务时，地址必须是本机服务，例如 `http://127.0.0.1:1224`；工具串行提交请求，不修改或关闭外部服务，其内部 CPU 线程也不由本工具保证。

## 识别和校对章节

| 方式 | 用途 |
| --- | --- |
| 自动（书签优先） | 通常选择这一项，优先找书签，再识别页面标题。 |
| 仅 PDF 书签 | 自带目录准确完整时使用。 |
| 仅页面标题 | 书签不可靠但正文可提取文字时使用。 |
| 扫描版：OCR 并分析 | 扫描页或需要重新识别文字时使用。 |

双击章节标题或起始页编辑；Enter 保存，Esc 放弃，F2 编辑选中标题。可手动添加漏掉的章节，删除误识别条目。

**起始页按 PDF 文件页序，从 1 开始。** 书上印刷页码可能不同。上一章结束页由下一章起始页决定，最后一章延续至文件末尾。

切换文件前会保存并校验编辑中的单元格。页码无效时会停留当前文件，先修正或按 Esc 放弃，避免把错误编辑带入其他文件。各文件保留独立识别模式、输出路径和校对结果。

分析完成进入“待校对”，不会直接自动导出。没找到章节时可手动添加；无文字层或 OCR 错误提示也需按实际情况处理，不能只看任务完成状态。

## 导出与文件保存

校对当前文件后，使用底部“导出 N 个 PDF”。选中多份已准备的文件后，“导出选中”会逐项校验；没有章节、缺输出位置或仍在处理的项会跳过并说明。

| 内容 | 保存位置与行为 |
| --- | --- |
| 原始 PDF | 只读，不覆盖。 |
| 整本 OCR PDF | 通常在原文件旁，以原名加 `_OCR.pdf` 保存；已存在或与其他输入冲突时增加编号。选择不同父目录作为输出位置后，OCR 文件也可存到该父目录。 |
| 分章 PDF | 每文件独立输出子目录；默认名称包含简短来源标识，同名来源也能区分。已有目录会使用新编号，不混入已有结果。 |
| OCR 检查点 | 软件目录中的 `.ocr-cache`，重试时先校验来源、页数及摘要再复用。 |
| 个人设置 | 软件目录中的 `umi-ocr.local.json`，记住引擎路径、主题、调度和性能设置。 |

导出先写独立暂存位置，成功后交付最终文件；失败或取消时清理本次半成品，已有成功文件保留。取消需要等待当前不可中断的 PDF 操作结束，不保证点击后立刻停止。

## 性能档位

| 档位 | OCR 实例上限 | 每实例配置线程上限 | 建议用途 |
| --- | --- | --- | --- |
| 节能 | 1 | 1 | 同时使用电脑，尽量保留资源。 |
| 均衡（默认） | 2 | 2 | 日常处理。 |
| 高性能 | 4 | 2 | 优先处理速度，接受较高资源占用。 |

CPU 数、可用内存、待处理工作和用户并发上限还会进一步收紧实际数量；内存未知时按单实例单线程处理。实例按需求启动，不因有多个文件而为每份文件再建完整池；空闲约 30 秒后回收自有引擎。

旧配置中的 `max_workers` 保留：0 为自动，1～12 是额外上限。均衡档中填 12 不会启动 12 个实例。资源栏显示设置上限和当前运行数。私有 Windows OCR 整个进程树共用一个 CPU 使用率上限，节能／均衡／高性能约为系统总 CPU 的 25%／50%／75%；不是为每个实例分别提供这个百分比。推理线程设置与模型内部辅助线程不是同一概念，界面分别显示已加载模型、推理设置和全局 CPU 上限。外部服务内部线程未知时会明确提示。

内存紧张时停止派发新重任务，显示等待资源；恢复后继续。不是硬内存隔离，单本复杂 PDF 仍可能有较高占用。限额可能增加总耗时；没有经过同条件完整对比时，不保证具体降幅或速度提升。

## 软件内检查与一键下载更新

1. 右上角“检查更新”打开更新窗口，再点击窗口内的“检查更新”。
2. 软件查询指定仓库的最新正式 Release，显示版本、说明、包类型与大小。网络失败、权限或限流会单独说明，不当作“已经最新”。
3. 有兼容更新时，选择保存位置并点击“一键下载更新”。下载在软件内进行，显示进度和速度，可取消或重试。
4. 下载结束后校验大小和 SHA-256；通过才交付最终文件。原有同名下载不会被覆盖；失败或取消清理本次临时文件，不能自动清理时显示路径。
5. 使用“打开所在文件夹”查看包。**下载不等于安装**：退出旧版后，完整解压新版或按包说明升级。

当前支持仓库中带对应 SHA-256 文件的源码 ZIP，会明确标注“需要 Python 环境”；没有兼容包、校验文件缺失或含糊时停止下载。检测不使用开发者凭据，不自动安装、执行或重启。关闭软件时若有在途请求或下载，会提示取消后退出。

升级保留个人设置和 `.ocr-cache`，可继续复用经过校验的 OCR 检查点。Umi-OCR 路径变化后重新配置。

## 主题、动画与快捷键

右上角切换暗夜模式或关闭动画，设置会记住。任务栏标题可平滑收起/展开；关闭动画后即时到达最终状态。运行中的任务可在文件列表切换查看。

| 快捷键 | 操作 |
| --- | --- |
| Ctrl+O | 选择当前 PDF 的兼容入口；添加多份请使用“＋ 添加”。 |
| Ctrl+Enter | 分析当前文件。 |
| Ctrl+Shift+Enter | 当前文件强制 OCR 并分析。 |
| Ctrl+N | 添加章节。 |
| Ctrl+E | 导出当前文件章节。 |
| F2 | 编辑选中章节标题。 |
| Delete | 章节表格聚焦时删除选中章节。 |

输入框、模态设置和当前文件处理期间会保护快捷操作，防止误删或重复启动。

## 常见问题

| 现象 | 处理方法 |
| --- | --- |
| 缺 Python 或依赖 | 安装含 Tkinter 的 Python，并用同一环境安装 requirements.txt。 |
| OCR 无法启动 | 确认完整便携版、有效主程序路径；外部服务还需检查 HTTP 开关和本机端口。 |
| 只读目录无法保存 | 选择可写的输出位置；软件目录也需要写入配置和缓存。 |
| 进度暂时不动 | 看阶段是准备、等待资源、OCR 还是合并；失败后保留缓存重试。 |
| 找不到章节 | 换检测方式或手动补充，不会自动把空识别结果导出。 |
| PDF 有密码 | 解密并另存后再导入。 |
| 更新检测显示没有可用新版本 | 对比的是远端正式版本；本地开发版本可能比远端更高。 |
