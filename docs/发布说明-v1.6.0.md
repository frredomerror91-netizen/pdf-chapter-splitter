# v1.6.0：多文件处理与软件内更新下载

本地源码版本的参考文档；本次仅同步文档，仓库代码与 GitHub Release 尚未升级到 v1.6.0。

- **检查并下载更新**：在软件内查看新版本与更新说明，一键下载发布包，显示进度并校验 SHA-256。下载失败或取消可以重试；校验通过后打开保存位置。下载不会自动安装、覆盖或重启软件。
- **多份 PDF**：一次选择多份资料，也可以继续追加；选择排队或并行处理，每份文件分别显示状态，单项失败不影响其他文件。
- **独立校对与导出**：切换文件保留章节修改，选中准备好的文件后批量导出；同名来源和已有输出分别保存，原始 PDF 保持不变。
- **节能、均衡、高性能**：OCR 实例由全局共享预算管理，不按文件数量成倍启动。单个小任务按需启动一个模型，空闲后回收；均衡默认最多两个实例，私有模型进程也受 全局 CPU 使用率限制。
- **界面与动画**：文件任务、当前文件设置和章节表格分区展示，支持深浅主题、任务面板收展和关闭动画。

## 使用前

需要 Windows、Python 3.10 或更高版本及 Tkinter。完整解压源码包，在软件目录安装依赖后双击启动脚本：

~~~powershell
python -m pip install -r requirements.txt
~~~

扫描版另行安装完整 Umi-OCR 便携版，在“识别章节 → 设置”中选择主程序。模型和引擎不包含在本源码包内。

## 几点说明

- 更新检测只读取指定仓库的正式 Release。当前支持下载有对应 SHA-256 文件的源码 ZIP，会明确标注需要 Python 环境；没有兼容资产或遇到限流时显示原因。
- 并行文件数是调度上限，OCR 实际实例数还受档位、用户并发上限和内存限制。外部已运行服务只串行调用，不修改其内部线程配置。
- 资源限制以减少占用为优先，可能增加总耗时；4页扫描样本各三轮中位耗时由约10.5秒变为13.7秒，单文件峰值内存没有下降；主要控制多文件并行的资源上限，不宣传提速或固定内存降幅。大型样本缺少有效旧版对照，详见验证记录。
- 任务列表在本次会话中保留。关闭重启后需要重新添加文件，大文件 OCR 可继续复用仍然有效的分块检查点。
