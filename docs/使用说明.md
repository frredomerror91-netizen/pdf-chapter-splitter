# PDF 章节拆分器 v1.5.0 使用说明

这份说明帮助你从下载软件开始，完成整本 PDF 的 OCR、章节校对和按章导出。先准备运行环境，再配置 OCR；日常使用只需选择 PDF 并操作工具界面。

## 一、首次安装

运行环境为 Windows 和 Python 3.10+，使用 Python 自带的 Tkinter 界面。源码包需要完整解压后运行。

1. 通过仓库“Code → Download ZIP”下载最新源码；本地源码发行包也可直接完整解压使用。
2. 完整解压到有写入权限的普通文件夹。
3. 安装 Python 时启用 PATH。打开项目目录的 PowerShell，执行：

```powershell
python --version
python -m pip install -r requirements.txt
python .\split_pdf_by_chapter.py
```

安装完成后可以双击 `启动章节拆分工具.cmd` 启动。

如果机器安装了多份 Python，请使用同一个环境安装依赖与运行程序。例如双击入口优先找到 Codex 的 Python 时，也要为该 Python 安装依赖。

## 二、首次配置 OCR

扫描版 PDF 需要本机 Umi-OCR。本工具的已验证版本为 Umi-OCR Rapid v2.1.5，可从 [Umi-OCR 官方 Releases](https://github.com/hiroi-sora/Umi-OCR/releases) 获取。

1. 完整解压 Umi-OCR，确认 `Umi-OCR.exe` 旁边有 `UmiOCR-data`。
2. 在章节拆分器左侧点击“OCR 设置”，选择该主程序。
3. 确认 Umi-OCR 的 HTTP 服务启用，主机为“仅本地”。默认服务地址为 `http://127.0.0.1:1224`；修改过端口时，两边需保持一致。
4. 保存设置。工具会连接已有服务，或在需要时隐藏启动主程序。

完整便携版也可以放入项目的 `tools/Umi-OCR/` 或 `tools/Umi-OCR_Rapid_v2.1.5/`。设置保存于 `umi-ocr.local.json`，其中的主程序路径仅适用于当前电脑。

大型 PDF 会创建临时独立引擎，因此必须提供可访问的完整便携版目录。

## 三、选择检测方式

| 模式或入口 | 适用资料 |
| --- | --- |
| 自动（书签优先） | 大多数教材。先找章节书签，没有可用书签时查页面标题。 |
| 仅 PDF 书签 | PDF 已有可靠的章节目录。 |
| 仅页面标题 | 书签不可靠，但页面包含可提取的章节标题。 |
| 一键 OCR 并分析 | 扫描版、部分扫描页、乱码文字层或需要重新识别的资料。 |

“无文字层时自动 OCR”默认勾选。自动模式下，整份 PDF 没有文字层且没有可用章节书签时，会自动 OCR。只有部分页面缺文字层的资料可直接点击“一键 OCR 并分析”。

## 四、完成一份 PDF

1. 点击“选择 PDF”。工具显示原文件路径和默认章节输出目录。
2. 点击“分析章节”，或选择“一键 OCR 并分析”。处理期间可查看进度，也可取消。
3. OCR 完成后查看章节表格，逐项核对标题和起始页。
4. 双击标题或起始页进行修改；缺失章节可手动添加，误识别的条目可删除。
5. 检查“前置内容”是否包含封面、目录和前言，以及各章范围是否符合教材。
6. 选择输出目录，点击“开始导出”。每个章节对应一个 PDF，OCR 文字层会随章节保留。

页码使用 PDF 的实际页序，从 1 开始。教材正文印刷的“第 1 页”可能位于 PDF 的第 15 页，编辑时应填写 15。

程序从下一章的起始页计算上一章的结束页，最后一章延伸至整份 PDF 末尾。

## 五、大型 PDF 自动分块

资料达到 100 页时自动启用，无需手工拆文件或指定分块数。

- 每块最多 50 页，尽量均匀分配；实例数按分块数、CPU 和可用内存自动调整，最多 12 个。
- 657 页会分成 14 块：13 块各 47 页，剩余 1 块 46 页。
- 首块输入准备好即开始 OCR；界面同时显示输入准备页数、OCR 页数、完成块数、活动实例和合并状态。
- 全部分块完成后，按原页序合并成整本 OCR PDF，再继续识别章节。
- 各块完成结果经过页数和摘要校验，合并时再次检查原文件及完整页数。

在“OCR 设置”填写并发上限：默认 4，0 为主动选择自动模式，1–12 表示希望使用的最大实例数。实际值还受资源预算约束。每个实例最多 2 个计算线程，默认 4 个实例最多使用 8 个 OCR 计算线程。CPU 每实例按至少 2 个逻辑核分配；可用内存保留 1 GiB，再为每实例估算 768 MiB。无法查询内存时保守限制为最多 2 个实例。

306 页会分成 7 块：5 块各 44 页，2 块各 43 页。默认上限 4 时使用最多 4 个实例，其余分块排队。在 20 个逻辑 CPU 和足够内存的电脑上，主动选择 0 自动模式可以为这 7 块各分配一个独立实例。手动设为 3 时，其余块自动排队。识别速度不会随实例数量等比例提高，页面尺寸、模型、磁盘和 CPU 都会影响实际表现。

准备阶段逐页检查取消，正在写入或校验一份 PDF 时需等待该次文件操作结束。进度条计入输入准备和 OCR 两部分；达到输入准备的全部页数，并不表示 OCR 已结束。

中间分块存储在项目的 `.ocr-cache/jobs/`。任务失败或取消后，可保留缓存并再次执行同一任务，程序复用仍然有效的已完成结果，以及已校验的完整输入分块。原文件、识别方式或引擎变化时，可能需要重新识别。

连续处理超过一小时本身不会终止任务；连续 15 分钟没有新增页面进度会报告停滞。并行速度受电脑性能及资料内容影响。

## 六、保存位置

| 产物 | 位置与用途 |
| --- | --- |
| 整本 OCR PDF | 原文件旁的 `<原文件名>_OCR.pdf`，可以独立打开、搜索和选择文字。 |
| 各章节 PDF | 指定的输出目录；默认是 `<原文件名>_章节拆分`，存在时选择新编号目录。 |
| 分块检查点 | 项目内的 `.ocr-cache/jobs/`，供大型 OCR 失败后继续使用。 |
| 个人设置 | 项目内的 `umi-ocr.local.json`，保存 OCR 主程序、服务地址、并发上限和主题偏好。 |

成功重新 OCR 同一份原文件时会更新同名 OCR PDF。失败或取消的大型分块任务不会发布不完整的合并文件。

OCR 已完成但章节分析失败时，整本 OCR PDF 仍然保留，界面会提示路径。关闭工具或选择另一份文件也不会删除这份成品。

## 七、暗夜模式与升级

在左侧“输出设置”勾选“暗夜模式”，界面立即切换，下次启动恢复该偏好。处理任务期间主题按钮暂时禁用。

升级软件前关闭正在运行的旧窗口。把新版源码完整解压到目标目录，保留本机 `umi-ocr.local.json`、Umi-OCR 便携版和需要继续使用的 `.ocr-cache/jobs/`，再从新版入口启动。若换了目录或电脑，在“OCR 设置”重新选择主程序。

不要只覆盖主界面脚本；v1.5.0 需要配套 OCR、分块和引擎模块。

## 八、遇到问题

- **找不到 Python 或依赖**：确认 Python 3.10+ 在 PATH 中，并用实际运行程序的 Python 安装 `requirements.txt`。
- **Umi-OCR 连接失败**：检查完整解压目录、HTTP 开关、仅本地主机和端口，重新保存“OCR 设置”。
- **OCR 进度长时间不动**：先看当前阶段。实例启动、文件写入及最终合并需要等待；准备与 OCR 有独立页数。缺失对象警告不必逐条处理，程序会复用恢复索引。取消后重试可以复用已验证检查点。
- **OCR 成功但没有章节**：打开保存的 OCR PDF，对照目录手动填写章节起点，或重新选择检测模式。
- **标题识别不准确**：校对章节标题和页码后再导出。目录、页眉或 OCR 字符错误可能影响结果。
- **加密 PDF**：先使用密码解密，或在 PDF 软件中另存为未加密文件。

源码仓库和发行包只包含工具及文档。Umi-OCR、模型、个人设置、原教材和处理结果需要在本机单独保留。
